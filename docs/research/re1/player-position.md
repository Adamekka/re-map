## RE1-PLAYER-003: room-local coordinates drive an explicitly approximate marker

Status: Candidate; pinned-source extraction, recorded movement replay and synthetic/browser regressions. No room has newly verified positional alignment in gameplay.

Game: Resident Evil Director's Cut USA, SLUS-00551, pinned executable SHA256 `0f589fb426fb4a3e067b3251e8ccd5e34df79322fdcc37ebff75aa670ac7fae6`. This work uses the owner's disc, committed Chemical Storage/Winding Passage savestate fixtures, and the twelve dated movement observations from RE1-PLAYER-002. The original runtime version and its limits remain recorded there. No emulator was opened or controlled for this change, and no user exploration history was modified.

The user approved approximate placement across rooms after learning that zero rooms had verified world-to-outline alignment. The old RE1-PLAYER-002 marker showed current-room identity and yaw above a wall. It remains the explicit room-only alternative for games or rooms without positioning support; it is not substituted for a failed required position read.

Read X/Y/Z together as twelve bytes starting at PS1 virtual `0x800C5158`, RAM offset `0xC5158`. X is signed little-endian 32-bit at block offset 0; Z is signed little-endian 32-bit at offset 8, PS1 virtual `0x800C5160`. All coordinate bits are retained. The middle four bytes are not interpreted by this feature. Read yaw separately through RE1-PLAYER-002. Both reads precede the final camera, room and lifecycle rechecks, without requiring the player to stand still. Failed or partial reads return a modeled read failure before changing tracker state. Position is fresh after every restore and is never stored in visit history.

`tools/build_position_bounds.py` verifies the executable and every RDT against the pinned manifest. The [reevengi RVD definition](https://github.com/pmandin/reevengi/blob/8130d5fd029a7548135bdbbff19b0b8e338bd42d/src/g_re1/rdt_rvd.h#L23-L38) and [reader](https://github.com/pmandin/reevengi/blob/8130d5fd029a7548135bdbbff19b0b8e338bd42d/src/g_re1/rdt_rvd.c#L56-L115), commit `8130d5fd029a7548135bdbbff19b0b8e338bd42d`, provide the source-format lead: twenty-byte records with `to=9` identify camera boundary quadrilaterals. The owned source arrays reproduce that layout. Termination and section bounds are checked. Two returned-Mansion sources retain a boundary for an unused camera; its ID is recorded separately and receives no mapping. Only numeric bounds, source identities and provenance leave the extractor.

Group actual source cameras by their native floor/region selection. Union the boundary coordinates within each group into `(left, near, right, far)`. The generated metadata covers 334 source RDTs, 363 source/region groups and 1,862 actual camera bindings, including all 118 outlined regions. This is source coverage, not verified positioning coverage. Startup requires this metadata, exact revision/source identities, complete camera coverage, valid nondegenerate bounds and agreement with native map selection. Multiple still-possible source variants must agree on bounds before an estimate is published.

For map floor bounds `(map_left, map_top, width, height)`, estimate `px = map_left + (X-left)*width/(right-left)` and `py = map_top + (far-Z)*height/(far-near)`. The candidate axis orientation follows RE1-PLAYER-002's positive-X/right, positive-Z/up comparisons. Camera boundaries are broader than traversable space, and the map is distorted, so these formulas are deliberately approximate. This does not retract RE1-MAP-002's rejection of camera-boundary polygons as global architectural outlines. Native numeric room contours still define the displayed floor plan.

Rasterize those orthogonal contours with even/odd scanline fill, retaining holes. An estimate outside its own floor cells is clipped to the nearest point inside those cells, with a 0.1-cell boundary inset and deterministic tie-breaking. This can flatten movement against a wall or shift position near bends. It never places the estimate in an adjacent room or a hole. An undrawn room, unavailable camera mapping or disagreeing source bounds yields an explicit room-only marker and reason. The legend and tooltip distinguish `You · approximate` from `You · room only`; no exact positional accuracy is claimed. RE2 retains its room-only marker.

Validation: replaying RE1-PLAYER-002's recorded Winding Passage points moves the estimate from `(147.1352,45.9263)` to `(147.8946,45.3910)` for the observed forward walk. Turns without X/Z movement preserve the estimate; restoring the earlier coordinates restores the earlier point. Chemical Storage's observed negative-X, positive-X and positive-Z movements likewise move left, right and up. These are replay checks of old observations, not new live room calibration. Browser regressions check translation separately from rotation, a centered pose marker, accuracy labels, stable room controls and a preserved viewport. Python checks cover malformed/missing configuration, source/camera disagreement, clipping, all outline areas and holes, read failure and coherent camera changes.
